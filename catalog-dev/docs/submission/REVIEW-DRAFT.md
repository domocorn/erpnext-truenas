## Description

Adds ERPNext using upstream Frappe Docker service commands and the standard TrueNAS library for storage permissions, MariaDB, ports and portals. Following review, the custom application lifecycle framework has been removed completely from the proposed catalog entry.

The package contains service/configuration wiring only: MariaDB, Redis cache/queue, the upstream configurator, backend, frontend, websocket, workers and scheduler. The configurator's short `ls apps` / `bench set-config` block follows upstream `compose.yaml`. Normal services retain the image entrypoint and upstream commands. There are no custom Python files, mounted application scripts, runtime supervisors, image/site markers, storage locks, RQ introspection, or automatic backup/migration/recovery jobs. Generated base-library copies are no longer committed.

**Manual setup and operations:** after installation, the user creates the first site interactively with upstream `bench new-site` in the backend shell, as documented in the README. The Administrator password field was removed. Until setup, the frontend can return 404. Backup, image upgrades/migrations and recovery follow upstream operator-managed procedures; this package does not automatically coordinate them or block runtime after an incomplete migration.

This is a fresh-storage redesign, not an in-place update of the previous guarded prototype. Existing prototype/production deployments have not been altered.
